## 简介

本故障排除指南旨在帮助用户解决在使用NOFX AI交易系统过程中遇到的各种问题。系统涉及多个组件，包括Go后端、React前端、多种交易所API以及AI决策引擎。我们将按照问题类型进行分类，提供详细的诊断步骤和解决方案。

## 启动问题

### 1. 编译错误：TA-Lib未找到

**错误现象：**
```
compilation error: TA-Lib not found
```

**根本原因：**
系统依赖TA-Lib库进行技术指标计算，但该库未正确安装。

**解决方案：**

#### macOS系统
```bash
# 安装TA-Lib
brew install ta-lib

# 如果使用Homebrew安装失败，可以尝试以下命令
brew tap homebrew/science
brew install ta-lib
```

#### Ubuntu/Debian系统
```bash
# 安装TA-Lib
sudo apt-get update
sudo apt-get install -y libta-lib-dev

# 或者使用包管理器
sudo apt-get install libta-lib0-dev
```

#### Windows系统
1. 下载TA-Lib安装包：[TA-Lib下载页面](https://github.com/mrjbq7/ta-lib/releases)
2. 安装到默认路径（C:\ta-lib）
3. 设置环境变量：
   ```cmd
   set TA_LIBRARY_PATH=C:\ta-lib\lib
   set TA_INCLUDE_PATH=C:\ta-lib\include
   ```

**验证安装：**
```bash
# 检查TA-Lib是否正确安装
go run main.go
```

### 2. 端口占用问题

**错误现象：**
```
port already in use: 8080
```

**解决方案：**

#### 方法1：修改配置文件
编辑`config.json`，更改API服务器端口：
```json
{
  "api_server_port": 8081
}
```

#### 方法2：终止占用端口的进程
```bash
# 查找占用端口的进程
lsof -i :8080
# 或者在Windows上
netstat -ano | findstr :8080

# 终止进程（Linux/Mac）
kill -9 <PID>

# 在Windows上
taskkill /PID <PID> /F
```

#### 方法3：使用不同端口启动
```bash
./nofx --port 8081
```

### 3. 配置文件加载失败

**错误现象：**
```
❌ 加载配置失败: parse config file failed
```

**根本原因：**
配置文件格式错误或缺失必要字段。

**解决方案：**

#### 步骤1：检查配置文件语法
```bash
# 验证JSON语法
cat config.json | jq .
```

#### 步骤2：检查必填字段
确保以下字段存在且正确：
- `traders` - 至少一个trader配置
- `api_server_port` - API端口号
- `leverage` - 杠杆配置
- 各个trader的必要字段（API密钥、AI密钥等）

#### 步骤3：恢复默认配置
```bash
cp config.json.example config.json
```

## API调用错误

### 1. 无效的API密钥

**错误现象：**
```
invalid API key
```

**根本原因：**
Binance API密钥配置错误或权限不足。

**解决方案：**

#### 步骤1：验证API密钥
1. 登录Binance账户
2. 进入API管理页面
3. 检查API密钥是否正确
4. 确认权限设置：
   - 必须启用"Futures"权限
   - 禁用"Enable Withdrawals"权限（除非需要提现）
   - 白名单IP地址设置正确

#### 步骤2：检查密钥格式
```json
{
  "binance_api_key": "YOUR_ACTUAL_API_KEY_HERE",
  "binance_secret_key": "YOUR_ACTUAL_SECRET_KEY_HERE"
}
```

**注意事项：**
- 不要在配置文件中包含引号
- 确保密钥长度正确（通常43字符）
- 不要与他人共享API密钥

**节来源**
- [config/config.go](file://config/config.go#L135-L140)

### 2. AI API超时

**错误现象：**
```
AI API timeout
```

**解决方案：**

#### 步骤1：检查网络连接
```bash
# 测试网络连通性
ping api.deepseek.com
curl -I https://api.deepseek.com
```

#### 步骤2：验证AI API密钥
```json
{
  "deepseek_key": "sk-your-actual-key-here"
}
```

#### 步骤3：检查API配额
- DeepSeek：检查账户余额
- Qwen：确认服务是否正常
- 自定义API：验证URL和密钥

### 3. 交易所连接失败

**错误现象：**
```
exchange connection failed
```

**解决方案：**

#### Binance连接问题
1. 检查IP白名单设置
2. 验证网络防火墙设置
3. 确认Binance服务器状态

#### Hyperliquid连接问题
1. 检查私钥格式（移除0x前缀）
2. 验证钱包地址格式
3. 确认测试网/主网设置

#### Aster连接问题
1. 检查API钱包地址
2. 验证私钥格式
3. 确认钱包权限设置

## 交易执行失败

### 1. 币安持仓模式错误

**错误现象：**
```
Order's position side does not match user's setting
```

**根本原因：**
币安账户设置为单向持仓模式，但系统需要双向持仓模式。

**解决方案：**

#### 步骤1：登录币安合约交易平台
访问：[币安合约交易平台](https://www.binance.com/zh-CN/futures/BTCUSDT)

#### 步骤2：修改持仓模式
1. 点击右上角的 **⚙️ 偏好设置**
2. 选择 **持仓模式**
3. 切换为 **双向持仓** (Hedge Mode)
4. 确认切换（**注意**：切换前必须先平掉所有持仓）

**节来源**
- [常见问题.md](file://常见问题.md#L1-L26)

### 2. 杠杆超出限制

**错误现象：**
```
leverage is over the maximum
```

**解决方案：**

#### 步骤1：检查杠杆配置
```json
{
  "leverage": {
    "btc_eth_leverage": 5,
    "altcoin_leverage": 5
  }
}
```

#### 步骤2：根据账户类型调整
- **子账户**：最大5倍杠杆
- **主账户**：BTC/ETH最大50倍，山寨币最大20倍

#### 步骤3：修改配置
```json
{
  "leverage": {
    "btc_eth_leverage": 5,    // 子账户：≤5x
    "altcoin_leverage": 5     // 子账户：≤5x
  }
}
```

### 3. 仓位大小错误

**错误现象：**
```
position size is too small/large
```

**解决方案：**

#### 步骤1：检查最小订单量
不同币种有不同的最小下单量要求。

#### 步骤2：调整仓位计算
系统会自动处理精度问题，但如果持续出现错误：
1. 检查账户余额
2. 验证杠杆设置
3. 确认币种精度要求

## 日志分析技巧

### 1. 决策日志位置

系统会在`decision_logs/`目录下保存详细的决策记录：

```bash
# 查看最新决策日志
ls -la decision_logs/

# 查看特定Trader的日志
ls -la decision_logs/my_trader/

# 查看最近的决策记录
tail -f decision_logs/my_trader/decision_*.json
```

### 2. 日志文件格式

每个决策日志包含以下信息：
- **Timestamp**: 决策时间
- **CycleNumber**: 周期编号
- **InputPrompt**: 发送给AI的输入
- **CoTTrace**: AI思维链输出
- **DecisionJSON**: 决策JSON
- **AccountState**: 账户状态快照
- **Success**: 是否成功
- **ErrorMessage**: 错误信息（如果有）

### 3. 常见错误模式

#### AI决策失败
```json
{
  "success": false,
  "error_message": "AI API timeout"
}
```

#### 交易执行失败
```json
{
  "success": false,
  "error_message": "invalid API key",
  "decisions": [
    {
      "action": "open_long",
      "success": false,
      "error": "invalid API key"
    }
  ]
}
```

#### 市场数据错误
```json
{
  "success": false,
  "error_message": "market data fetch failed",
  "candidate_coins": []
}
```

### 4. 日志分析工具

#### 使用jq分析日志
```bash
# 查看所有成功的决策
jq '.[] | select(.success == true)' decision_logs/*.json

# 查看最近的错误
jq '.[] | select(.success == false)' decision_logs/*.json | head -10

# 分析交易成功率
jq '[.[] | select(.success == true)] | length' decision_logs/*.json
```

#### 性能分析
```bash
# 分析最近100个周期的表现
jq '.[] | {timestamp, total_pnl, position_count}' decision_logs/*.json | tail -100
```

## 性能优化

#### CPU使用率过高
```bash

top -p $(pgrep nofx)

```

#### 内存使用优化
```bash
# 检查内存使用
free -h

# 清理缓存（Linux）
sync; echo 3 | sudo tee /proc/sys/vm/drop_caches
```

### 2. 网络优化

#### API调用频率控制
```json
{
  "scan_interval_minutes": 3  // 推荐3-5分钟
}
```

#### 连接池优化
```go
// 在API客户端中设置连接池
client := &http.Client{
    Transport: &http.Transport{
        MaxIdleConns:        100,
        MaxIdleConnsPerHost: 10,
        IdleConnTimeout:     90 * time.Second,
    },
}
```

### 3. 存储优化

#### 日志轮转
```bash

find decision_logs/ -name "*.json" -mtime +7 -delete
```

#### 压缩历史数据
```bash
# 压缩旧日志文件
gzip decision_logs/*.json
```
